# Repeated quiescent images and observed thread lifetimes

Status: accepted for bounded implementation; native calibration remains open.

The v1 runtime profile deliberately accepts one selected bootstrap exec. Compact Python/Node launches require subsequent same-PID image transitions, and ordinary observed thread lifetimes must remain distinct across those transitions. Add a separately selected v2 program and strict entry point; do not relax v1's marker, public API or rejection behavior.

The C producer exposes the fixed `rt_images_program` marker `glue-runtime-images-v2; quiescent-exec; no-process-creation`. A separate `rt_images_create` factory uses one private transport engine with closed v1/v2 selection. V1 still requires exactly one entry/success; v2 requires balanced, nonoverlapping exec entries/successes bounded at sixteen. No public mutable profile, custom D source or weaker completion option is added. Unsupported creation/spawn, rights and Mach routes are retained before whole-capture failure.

The Python `pair_runtime_images_raw` entry point consumes original physical records once and validates the complete transport before any pairing result. Reuse the v1 canonical launch-evidence checks and a small common private transport parser with independently fixed program bytes. Preserve every bootstrap record and the original initial gate/status/selected-exec checks. Never accept caller-built pairs, image declarations or successful-effect assertions.

Each exec starts only with one active current-image actor, no other live or reserved thread, and no other pending call. It closes through the source-defined distinct new-thread exec-success, process start and LWP start sequence. Retain its old entry and any canonical EJUSTRETURN projection as a transition, not an ordinary successful call. Image replacement retires the old user image without claiming that a numeric TID is a native generation. Later requested path and artifact identity remain absent; the initial source-conditional artifact hash must never be copied to later images.

Observed LWP declaration/start/exit events establish bounded capture-local thread instances, including explicit generations when a numeric TID is reused only after observed retirement. They do not establish kernel object IDs, FD tables, effect order, rights or native identity. Exec while another actor is active/reserved/pending, ambiguous event ordering, thread reuse before retirement, unresolved lifetime, later exec failure, unsupported process creation/rights/Mach, and arbitrary unclosed calls refuse the whole result. Nonreturning exit entries remain explicit outcomes correlated to their observed lifecycle retirement; no successful return or harmless effect is invented. Any additional nonreturning thread-call admission must be supported by exact source and an explicit closed rule.

Native/provider/source coverage calibration, generic runtime launch-recipe adoption, protected target identity for later images, output capability seeds, filesystem/VM semantics, state-feed eligibility and full extraction acceptance stay open/false. No provider, VM, sudo or SIP action is part of this source implementation.

Controls must prove old/new profile cross-refusal, exact actual C producer agreement, one/multiple/bounded exec sequences, quiescent guards, old/new TID and image separation, ordinary thread declaration/start/retirement/generation boundaries, terminal calls, unsupported effects, complete-stream late failure and immutable fresh serialization. Preserve prior receipts and retain new source-frozen controls on the available Python versions.

Source clarification: canonical EJUSTRETURN probes can race after new-image startup; v2 retains them only against their unique original exec entry and before an observed old LWP exit. They are retired-kernel context, not live actors or successful ordinary calls. P_REF_SHADOW records are independently grounded as old PID-hash-replaced proc objects and remain unbound context: no image/address generation, live actor retirement or capability is inferred from them. Unresolved shadow attribution stays explicit and all state/native/full-admission flags remain false. The complete private initial actor set must resolve before handing internal bootstrap state to v2, so an unmatched reserved declaration cannot disappear.
