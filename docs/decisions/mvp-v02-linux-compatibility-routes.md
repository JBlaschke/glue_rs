# Native Linux Python input-route compatibility

29 October 2026. R04 requires actual provider/environment/archive-route evidence
beyond the 24 ordinary-environment native cases. A complete ordinary case set
does not demonstrate uv-created environments or direct full/stripped PBS input.

Add an explicitly selected compatibility extension to the existing native Linux
runner. Keep its original 24-case and five-budget scope unchanged. The extension
runs seven additional shared V02 recipes: direct PBS 3.13 full, install-only and
stripped archives, plus uv-created source, module, console and native inputs.
Each uses the existing complete offline process-tree trace and oracle controls.
Preparation installs no application dependencies: supplied runtime archives,
uv and the previously provisioned native wheel inputs are independent test inputs.

Bind the target-matched official runtime/tool archives by their recorded digests.
Retain the actual environment-preparation receipt, archive input identity and
complete V02 checker inputs. A separate summary must reject missing, failed,
misidentified or wrong-route cells. Tests of this summary establish no native
compatibility; only the retained native executions and independent replay can do
so. uv's executable hook is explicitly pruned by the fixture build command, with
the same documented semantic limitation as the existing uv recipe.

The extension does not replace the current acceptance evidence or refreeze any
budget. It establishes no complete matrix, additional-patch/abi3 acceptance,
macOS tracing/signing, unrestricted asynchronous-I/O observation or final M2
sign-off. It follows the same recorded syscall-fallback trace environment.
