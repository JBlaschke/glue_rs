# Typed stopped-runtime lifecycle status bridge

The fixed stopped-runtime backend deliberately refuses the old rt_snapshot API. A later controller therefore needs a distinct typed diagnostic that exposes its actual late cleanup and writer-close outcomes without changing the old snapshot ABI or granting authority.

Add a separate rt_stopped_status type and pure getter for the stopped class only. The status contains the existing observed-prefix identity and an exact copy of the backend lifecycle view, plus explicit profile/layout/status versions and false native, state, exemption, quiescence and full-flags authority fields. The lifecycle events field remains the total original outer event count; common0..18 and extra19..23 counts remain explicitly in the identity. This does not reinterpret rt_snapshot as accepting the new class.

The getter clears output then refuses null or foreign-class inputs, copies only live owned backend storage, derives identity through the existing pure getter, and performs no callback, I/O, clock, owner query or mutation. The caller must keep a live non-aliased backend and output storage, with no concurrent mutation. After rt_destroy the caller has a null backend; dereferencing an old freed alias is outside the API contract. Returned fields retain actual first/close/writer-close errors, masks and native errno, start/stop/drain/close attempts, resources_closed, deadlines and binding. The getter infers no successful session or cleanup from these observations.

The existing prefix getter, old public snapshot layout/behavior, all factories, options and fixed program bytes stay unchanged. No TS, runner, controller, native kit, source admission or provider adoption is added. This is an independent source feature; its baseline is the repaired, frozen producer. Focused controls use actual backend operations linked to source-isolated libdtrace stubs, with exact internal-state comparisons before and after each getter call. They cover complete closure, earlier failure with successful cleanup, late clock failure after actual close, unresolved writer close, missing drain/END, null and foreign class refusal, and existing default API behavior. No provider or signal operation executes.
