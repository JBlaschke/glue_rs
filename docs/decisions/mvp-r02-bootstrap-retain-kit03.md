# R02: preserve the completed kit03 installation

Kit03 completed its four-case nontracing packet `da1aaf9a396020b3`. Its protected
fixture prefix must be absent before a new tracing installation. The earlier
kit02 retention script deliberately requires a pre-case stage and cannot be
reused. Preserve kit03 by a separate, once-only same-parent rename to the fixed
fresh sibling `GlueMVPFixtures-retained-1b85f0ac-da1aaf9a`.

A fixed read-only inspection packet records only the live prefix, retained kit02,
and explicitly named historical bootstrap stage, user-work, launch and output
roots. It reports absence or complete bounded physical trees, exact directory
rosters, full modes, UID/GID, device/inode, file sizes, single links and SHA256,
with before/after identity checks. It rejects symbolic links, special files,
ACL-bearing entries and excessive depth, entries or bytes. It records strict
signature checks of the three live kit03 payloads without executing them. Core
Perl supplies bounded directory/file operations and JSON/SHA256; no guest Python
installation or arbitrary command/path interface is introduced.

Mutating retention is initially unconfigured and refuses before I/O. Later
source activation must bind the actual fresh normal-boot deployment proof,
independent review, complete fresh physical inventory and literal new-boot
identities. Historical kit and packet hashes identify their unchanged bytes;
old device/FSID tuples are never current observations. The root phase verifies
all approved preserved trees before the move, runs `/bin/mv -n` once, requires
source absence and unchanged destination inode/tree, then verifies all preserved
checkpoints again. A fixed exclusive private attempt record, created only after
validation and before the move, prevents another packet from retrying an uncertain
rename. This new receipt is retained on every outcome. Any uncertainty stops without retry, cleanup, chmod, chown,
ACL repair or target execution. Failed receipts remain private, and success is
not inferred from a partial receipt or rename exit status alone.

The root-owned nonwritable parent and exclusion of concurrent privileged mutation
are workflow preconditions. Root must coordinate an exclusive owned-VM staging
slot, with no other privileged test, installation or manual fixture changes from
inspection through retention. An ordinary lock file does not exclude another
root process, and this tool makes no atomic hostile-mutator exclusion claim.
Perl stat timestamps have seconds resolution; identity/hash comparisons require
this stable coordinated namespace and do not exclude adversarial rapid writes.
Fresh native inspector proof verifies the current mount/ancestor policy; no
source-only test substitutes for that guest observation or coordination.

Actual root command argv, literal status and both streams are retained separately.
Preparation and read-only inspection do not activate retention. This maintenance
step changes no security setting and proves neither tracing, kernel exec,
extraction nor full R02/M2 acceptance. Existing completed exports, staged packets
and failed checkpoints remain unchanged.
