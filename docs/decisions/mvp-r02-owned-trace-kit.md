# R02: prepare a guarded host-only tracing kit profile

Add a separately named tracing kit builder for the fixed context-probe,
owned-trace-runner and make-request artifacts. Reuse the existing bounded kit
codecs, physical tree/proof/source-lock checks, exclusive output handling,
double-build/signature controls and catalog encoding through frozen internal
source-defined policies. Do not copy the entire builder or select policy by
CLI/environment/module-global mutation. Preserve the legacy construct defaults,
CLI, enabled-SIP proof policy, schemas, registry and recipe behavior.

The tracing CLI has only guest-proof, inspector-kit and new output paths. Its
distinct registry starts with null source revision and empty source map,
compile lists and proof list; it must refuse before source/proof/output/build
work. This step registers no current source or actual deployment observation.
The eventual fixed tracing recipe names the reviewed parent/coordinator/backend
source paths, but no mutable parent bytes or historical kit identities become
admitted inputs. Root owns final source registration and later integration.

An independently reviewed fresh proof must retain exact disabled-SIP command
bytes under a separate tracing policy, the unchanged inspector provenance,
exact model/kernel/OS admission and complete literal device/FSID observations.
Enabled-SIP proof belongs only to the legacy builder; neither profile accepts
the other or normalizes proof bytes/mount identities. A later tracing-policy
reboot requires a fresh observation and catalog rather than reuse of old tuples.

Keep BA_PREFIX and canonical catalog encoding unchanged. The tracing profile
has distinct registry, recipe, build-identity, result/failure schemas and a
separately compiled owned-trace-runner artifact. Only that artifact defines
GLUE_OWNED_TRACING and links libdtrace. Its Mach-O policy requires exactly
libSystem plus libdtrace; context-probe and make-request retain libSystem-only
policy. Unknown artifact selectors, missing or additional dependencies, weak/
reexport/unsupported loads and all existing architecture/OS/signature-layout
failures refuse. There are no runtime library/trust/hash/SIP/profile overrides.

Use synthetic proof/parser fixtures and refusal/recipe/load-command controls,
including the existing legacy kit suite. SDK compile/link-only metadata checks
may never execute the resulting binaries or a provider. Do not access actual
guest exports, build an admitted native kit, change SIP, use sudo/network,
install, retain or publish artifacts. Native tracing calibration, independent
tracing receipt checking, installation and full R02/M2 acceptance remain later
work, requiring separate review and actual evidence.
