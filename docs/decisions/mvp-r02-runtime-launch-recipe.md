# Execute a fixed compact runtime recipe in the owned object child

29 October 2026. Source implementation decision. Runtime native admission, later
exec-epoch/CLOEXEC tracking and full MVP/Mac oracle acceptance remain open.

Add a separate source-selected runtime profile. The default compiled runtime
catalog is NULL and its admission registry is exactly empty. The default probe
request/catalog/result profile remains closed. No CLI or environment switch can
replace a compiled runtime recipe, target, source/proof pin or admission policy.

A pure fixed-capacity planner copies a bounded compiled argv vector. The tested
compact vector is absolute protected glue, run, absolute app.glue, -- and one
literal case argument. The initial environment is exactly empty. No shell,
expansion, PATH lookup, inherited environment, caller trust boolean or app-ID
allowlist is introduced. The exact target, argv/environment bytes and existing
R01 recipe/lock identity enter canonical runtime catalog/request binding. R01
continues parsing and verifying its own distribution/runtime dependency closure;
C does not implement another packaging parser. Recipe-closure provenance and
native deployment remain conditional until independently reviewed actual proof.

The native entry selects only its compiled aarch64-apple-darwin profile and
rejects an unconfigured catalog before effects. It admits and hashes the actual
protected launcher leaf with a separate finite launcher bound, retaining the
probe's existing four-MiB bound. A separately admitted fixed sibling CWD is
opened relative to the already admitted GlueMVPFixtures parent and checked by
the existing directory metadata policy. It is independent of the distribution
parent, held until cleanup, and bound to request/READY native device/inode.

The real child still resets signals, maps stdio, verifies credential drop,
selects the held CWD, performs numeric five-FD closure and captures descriptor
objects before READY. Only matching GO, strict EOF and checked gate close can
release the signal mask and reach execve with the copied fixed plan. The CWD
handle is borrowed, omitted from the keeps and closed by TD in the child; the
parent owns its separate reference. Held output references, absolute attempt and
cleanup deadlines, no-replay status writes and exact owned-child reap/close
rules remain intact. Every partial/late setup failure exits without a target.

The runtime result is distinct from the context-probe result. It captures
stdout/stderr as bounded opaque bytes with byte counts/hashes, original raw wait
status and actual exit/signal observations; it never decodes NP data or infers
post-exec credentials/root-regain from application output. Oversize/read/close
and execution failures stay failures with retained observations. Capture limits
bound retained reads; they are not hard preemption or a filesystem quota.

The first bootstrap-to-glue exec has an empty environment. Existing compact
code may create its own declared environment for a later Python/Node exec.
Actual macOS host checks may also spawn sw_vers and a reader thread first.
Consequently a one-exec runtime reader is only a foundation. Later adoption
requires complete process/thread joins, quiescent successful exec epochs and
CLOEXEC/mapping transfer; these events cannot be hidden or whitelisted away.
The new profile remains untraced and full acceptance/exec proof stay false.

Controls distinguish pure plan/request/catalog data, source-isolated production
child models, ordinary unprivileged native helpers and any explicitly modeled
credential/admission step. No privileged credential transition, configured root
bootstrap, provider, VM, sudo or SIP change is performed. Configured historical
registries and shared CI/status files remain untouched. Root owns subsequent C
and separate reviewed C-to-R registration.
