# Fixed runtime recipe tracing runner

This separate source wrapper joins the real owned runtime parent/child and
original output/gate witnesses to the fixed fixture2 session and v2 RT backend.
The default compiled runtime catalog remains NULL and its registry remains
empty. No configured deployment, trace-provider run or native admission is
supplied. The CLI accepts only the existing request/output arguments.

The wrapper includes the unchanged untraced runtime profile before defining
its tracing markers. Ordinary runtime wrappers still reject a direct traced
build. Eight fixed translation units share the same traced `nr_attempt` layout,
including the attempt-bearing admission and witness modules; pure catalog,
request and launch helpers are reused directly. There is no runtime backend,
D-source, acceptance or trust selector.

The parent compares actual READY and retained original held-output samples
before backend creation. The session must consume provider readiness and BEGIN
before the sole GO claim. BIO observers retain the original deadline while
pumping the provider. Confirmed original GO bytes, failed partial/full delivery
and actual close outcome are preserved separately even when trace reporting
fails. Complete runtime status is1024 bytes; failed prefixes remain opaque and
bounded by1537. Cleanup keeps actual owned-child reaping/kill eligibility and
once-only stop/drain/close/report/destroy. Pure fault snapshots can precede the
one final retained snapshot; no callback or snapshot occurs after destruction.

An early unclosed output or CWD reference reports failed parent closure and
cannot promote a result. Parent ownership reporting occurs before backend
snapshot/destruction. Final result promotion stays last. The distinct sidecar
schema is `glue-runtime-recipe-trace-session-diagnostic-v1`; the result schema is
`glue-owned-runtime-recipe-traced-diagnostic-v1`. The sidecar references original
witness artifacts and retains RT exec counters, while native admission, output
capability authority and full acceptance remain false. Counters do not replace
the independent complete-stream image/recipe reader.

Build the unconfigured validation binary with `sh build.sh /absolute/new/path`.
An optional catalog translation unit is build-time development input, not an
admitted runtime kit. The SDK-link check never runs a provider. Focused controls
use actual parent/trace/files/witness/session source with explicit POSIX and
backend models. They do not run a configured bootstrap, tracer or application.
The existing ordinary child fixture separately models protected admission and
credential mutation.

The RT profile still watches one PID and refuses unsupported creation, rights
and Mach routes. Generic offline/quarantined-input and environment integration,
post-exec output backing, complete FD/VM/Mach/process semantics, native provider
calibration, the compact Mac corpus and budgets remain open. In particular,
READY output association is before exec: kernel inheritance policy can close or
replace stdio, so clear CLOEXEC cannot grant a later output exemption. No VM,
sudo or SIP action is part of these source controls.
