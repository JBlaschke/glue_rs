# Fixed positive/denied tracing calibration lane

This is a separate source-only two-case packet and physical streaming checker.
Both CLIs currently refuse before supplied-path/helper reads or output creation:

```
python3 -B prepare.py --kit ABS --output NEW
python3 -B checker.py --packet ABS --evidence ABS --run-receipt ABS
```

There is no case, PID, target, provider, policy, proof, hash or approval override.
`APPROVED=None`, `EXECUTION_ENABLED=False` and `CHECKING_ENABLED=False` are not
admissions. The renderer additionally requires the original disabled state and
emits literal0 plus UNAPPROVED-CALIBRATION. The checker CLI has an unconditional
later-activation refusal even beyond its early guard: packet/kit/receipt admission
must be implemented and reviewed with actual identities, not enabled by changing
constants. No actual kit, proof, output, provider or native program is used here.

`plan_from_identity`/`render` are pure developer helpers for synthetic plans and
hard-disabled script text. Plans have distinct schema/paths, positive then denied,
fixed10000/2000ms budgets and exact evidence names. The root-stage template
admits only install, install-context export, two case selectors and their fixed
export roles. Ordinary requests are generated before denial changes cwd mode.
Current exact SIP-disabled/model/OS/kernel/inspector/IDs/groups/all five component
observations must match before authentication. Native invocations have fixed
clean environments and exact NUL argv; wrapper status0 is distinct from native
positive0 or denied1.

The existing four-case preparer remains APPNone/EXECfalse/SIMNone and renders
identical hard-disabled behavior. Only its strict kit loader body moved to the
small pinned `../bootstrap-trace-vm/kit_contract.py`; its early SIM guard still
runs before loading that helper. No module policy globals are overridden.
Shared core/wrapper/gates/raw/case/codec source pins are checked. Native sources,
both builders, registries and historical nontracing policy remain unchanged.
The normalized original loader body is pinned to f8e50d1 and exercised against
an independent valid injected verified-tree boundary plus terminal mutations.

The new templates preserve bounded physical root-owned promoted result/trace
checks and pending absence BEFORE any native-output raw enumeration/read/hash.
Unchanged metadata gates require exact positive clean lifecycle or pre-READY
denied ERROR/EOF and its three closed wait/kill race pairs. Then exact native
rosters are ten files positive/six denied; failed/uncertain states remain private,
with no raw export, generic failure bucket, metadata collector or restoration
trap. Denied mode restores only after its closure gate and physical roster.
A bounded checked install-context device/inode receipt is captured before cases
and rechecked around denial; CaseBinding never derives that context from the
request/READY/NP fields being checked. Whole-prefix absence remains mandatory:
completed kit03 needs separately reviewed fixed retention before another install.

Normal outer0 plus exact complete0 two-case batch precede final batch/receipt
inventory/export. No SIM or trailing execution is part of this packet; existing
SIM_POLICY/refusal stays unchanged. A failed positive attempt may prevent all
completed batch export; private wrapper/native receipts are not a calibrated
failure or a collector. The pure SIM metadata predicate is not adopted.

The concrete host API `check_export(plan, catalog, evidence, run_receipt)` checks
physical local exports only with caller-trusted canonical plan/catalog provenance.
It does NOT load/authenticate a packet or activate CLI admission. It verifies the
four-file normal outer receipt, fixed small control/promoted metadata first,
then exact inventory/hashes before raw reads. Leaf opens are no-follow/nonblocking
so a FIFO refuses before transfer. Held regular files are single-link, own-user,
not group/world writable and bounded. Trees/nested directories are own-user0700;
all ancestors are opened physically without symlinks. Bounded scandir iteration
has a fixed entry ceiling; aliases/extra/missing/special members refuse.

Positive raw events are streamed once with readline8192, at most8191 bytes per
complete LF line,128MiB aggregate/one million events; program16KiB, probes1MiB/
8192 inventory, errors64KiB and empty. Total evidence cap is135MiB (plus bounded
manifest for the local reader). Legacy8MiB/64MiB helpers are unchanged. Source
exceptions, file changes, read/close failures or trailing data return no facts.
The exact pinned raw validator yields RawFacts; the complete case checker then
links both catalog/request/BW/NP/result/sidecar cases and raw/session counters.
Reported controller/child PIDs are cross-bound observations, not independently
attested ownership. Frozen PairFacts retain tracingtrue/execfalse/fullfalse.
No original clock origin/budget proof or DTrace/monotonic equivalence is claimed.

Run `python3 -B test_calibration.py -v`. Sixteen groups use complete independent
C/BW/NP and scalar-transport synthetic pairs before mutations; original serializers
are transcribed from the accepted case/raw control fixtures, not a producer or
validator generator. Tests cover all denied pairs, physical exact exports,
strict receipts/schema/context/case links, gate-before-raw, tail/bounds, source
and close failures, bounded FIFO subprocess, private directories, loader body
normalization/behavior, helper pins, closed CLI and generated shell syntax.
Only a small read-only operation helper runs with injected host commands;
no generated privileged phase is executed. These controls establish no actual
provider/ABI calibration, installation, export safety under privileged mutation,
source/proof admission, kernel exec, extraction or R02/M2 acceptance. Stable
owned namespace/no concurrent privileged mutator remains a workflow precondition.
