# Exact runtime launch and original output witness

`runtime_recipe.py` adds the fixed `pair_runtime_recipe_raw(...)` entry point for the generic runtime recipe. Its frozen `RuntimeRecipeEvidence` requires the original request, catalog, standalone launch plan, complete status stream, launcher artifact, four-sample output witness, gate-delivery record and confirmed GO prefix. It never accepts a match boolean, a predecoded operation list or a caller-selected status prefix.

The reader checks the exact `GLUERR01` request, `GLUERC01` catalog and embedded `GLUETL\0\1` plan produced by `bootstrap-runtime-runner/runtime_request.c`, `runtime_catalog.c` and `target-launch/target_launch.c`. It enforces the 16 MiB launcher bound against the supplied artifact's actual size and SHA256, the independent sibling CWD, literal argument boundaries, the fixed Darwin target and empty environment. Catalog source, recipe and R01 lock hashes are retained claims; matching those bytes does not establish a reviewed build or protected installation.

The entire successful `status.bin` must be exactly 1024 bytes: a complete object-profile READY512 followed by EXEC_ATTEMPT512. Both records bind the original request and PIDs, and all fields, unused rows and reserved bytes are checked. Any extra record, ERROR, truncation or trailing byte refuses. The actual runtime topology has read-only character backing for `/dev/null` stdin, two write-only regular outputs and two nonblocking FIFO gate/status endpoints. The existing public probe v1/v2 launch profiles retain their original topology and refusal behavior.

`GLUERW01` is the parent's fixed 320-byte original-observation record. Its four 40-byte rows remain in their original order: first stdout, first stderr, second stdout, second stderr. The reader requires complete successful observation, independently compares both rounds, and recomputes each match against child READY slots1/2. Held descriptors must be distinct, at least3 and CLOEXEC; child stdio CLOEXEC must be clear. Parent and child descriptor flags are deliberately not required to match. Their complete backing metadata and full status flags must match, and both outputs must be distinct single-link regular write-only backing. Status bits are preserved rather than reduced to access mode.

`GLUERD01` is the fixed 240-byte record of the actual gate operation, distinct from the confirmed `go-prefix.bin` bytes. Successful delivery requires a complete 64-byte confirmed GO prefix, successful write and close, zero BIO error fields, and exact request/catalog/READY/PID bindings. Actual BIO success has `result.bytes_moved == 64` and `error.bytes_moved == 0`. A failed operation remains failure even when its complete confirmed prefix equals valid GO. These rules follow `bootstrap-runtime-runner/runtime_witness.c` and `bootstrap-io/bootstrap_io.c`; the reader does not reconstruct a successful delivery from an intended GO message.

After checking these bounded assets, the reader invokes the fixed runtime-images v2 physical transport and image/thread walk. That walk validates the complete original raw stream once before any successful public result. A small private `_pair_with_launch` bridge shares that walk; both existing public launch factories remain fixed and continue to validate their own evidence. Later images retain opaque requested paths and artifact identities. Unsupported process creation, rights or Mach routes, malformed or incomplete transport, ambiguous image/thread lifetimes and late faults refuse the whole capture.

The result includes both original sample rounds and two conditional output seeds bound to the aggregate evidence and complete raw-capture digest. Their keys are capture-local provenance values. Equal metadata and repeated samples do not prove native origin, OFD identity, kernel generations, paths, atomicity, exclusive ownership or unchanged binding over later intervals. In particular, independent opens can match. A trusted owned-parent integration must establish the quiescent child and held-reference lineage separately. All native authentication, output-exemption authority, state-feed eligibility and full-trace acceptance flags remain false.

Run `python3 fixtures/mvp/macos-trace/runtime-boundary/test_runtime_recipe.py`. The 24 focused controls include independently constructed RR/RC/TL and wire bytes, an actual C witness encoder differential check, full failed delivery, all witness/delivery truncations, complete-status refusal, launcher and copied-argument limits, full flag preservation, sample/READY mismatch, late raw faults, single stream consumption and immutable fresh serialization. The C codec control executes no parent runner, provider or privileged tracing. Existing `test_runtime_boundary.py` and `test_runtime_images.py` controls remain required regressions.

This feature connects exact generic launch bytes and original held-output observations to the existing strict raw reader. The fixed traced-runtime adapter, subsequent FD/effect policy, authoritative native corpus and calibrated budgets remain separate delivery work. The current generic native profile explicitly refuses compilation with `GLUE_OWNED_TRACING`; this reader does not bypass that gate or supply runtime admission.
