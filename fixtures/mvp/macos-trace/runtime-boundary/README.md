# Fixed runtime profile and selected image boundary

This module adds a separately named, fixed C capture backend and strict Python image-aware reader. It establishes bounded call correlations across the reviewed bootstrap's first exec. It supplies actual producer and reader source, while the legacy owned backend, its byte program and every legacy refusal remain unchanged.

It is not yet adopted by the protected runner/catalog or a configured kit. It never runs a provider in its controls. Native calibration, protected-target attestation, held-output capability seeding, state-feed eligibility and full R02 acceptance remain false. The catalog still selects `context-probe`; generic Lua/Python/Node target selection and full process-tree coverage remain later work.

## Producer and strict transport

`rt_program()` emits a fixed program with a byte-significant second-line marker. It accepts only the sole target PID; no input selects weaker clauses or completion. `runtime_trace_backend.c` explicitly derives the reviewed owned transport into the separate `rt_` API. The six native files have their own controls. See its header for ownership, original deadline, output, error/drop, drain and cleanup contracts.

The runtime backend retains an unsupported route's serialized record before refusing the session. Creation/spawn events, opaque Mach traps, the twelve named creation/rights/image BSD routes, repeated exec entries/successes and missing selected-exec completion cannot yield clean completion. The fixed program intentionally watches only the selected PID; recording a creation does not establish descendant coverage. No legacy source pin is edited to admit these new files.

`pair_runtime_raw(program, probes, errors, event_lines, owner_pid=..., target_pid=..., contract_bytes=..., launch_evidence=...)` validates the independent exact program template, complete inventory, raw widths/offsets, all header/scalar identities, PID/parent context, enablings, bounds, empty error stream and complete BEGIN/terminal/END transport. It consumes the physical iterable once. Every event's probe identity and all scalar words survive in immutable `source.phases`; the exact physical stream has a byte count and SHA256. No public result is returned before exhaustion. Iterator/source faults propagate. A semantic `BoundaryValidationError` contains only the completely validated immutable `capture`, without an accepted prefix or fabricated calls. A transport failure has no capture.

The reader reuses only the fixed, hash-checked low-level owned event/inventory/source-contract parsers. It does not call the legacy whole-stream validator or pairer with relaxed switches. Both old and new readers reject the other's program bytes. Its import reads only fixed helper code to check identities; public calls perform no asset or filesystem I/O.

## Exact launch bytes and their trust boundary

`LaunchEvidence` contains the original canonical request, catalog, 512-byte object READY, distinct 64-byte GO, 512-byte EXEC_ATTEMPT and protected-target artifact bytes. `validate_launch_evidence()` checks their complete framing/reserved fields, exact request hash and owner/target binding, catalog hash, target size/hash, fixed catalog path/leaf, credentials/groups/CWD, five descriptor rows, closed Darwin descriptor topology including nonblocking gate/status access, source/recipe identity fields and sequence. It accepts no caller `exec_ok`, `objects_matched`, prebuilt pair or normalized operation assertion.

These checks establish consistency of supplied bytes. The result retains their identities and a length-framed aggregate digest; callers retain the original evidence bytes. The source/recipe hashes in the catalog remain claims from the trusted collector, not independently verified build provenance. The PID/owned-child lifetime, actual protected installation, compiled bootstrap origin, GO delivery, successful parent held-handle match and native origin of the supplied evidence still require controller/native witnesses. Hashing an arbitrary target artifact does not prove that the kernel loaded it. Raw execve words are opaque addresses; the reader does not dereference them or infer pathname equality. All corresponding admission/attestation/capability flags stay false.

## Bootstrap and image handling

The complete prefix is retained and paired. A single initial return can be explicitly represented as an `AttachmentReturn`, only as event 2 after BEGIN, on the sole bootstrap thread, before any observed entry. Its closed routes are canonical successful READY-write tail (`write`/`write_nocancel`, 1–512 bytes), GO read already in flight (`read`/`read_nocancel`, 1–64 bytes), or gate poll (`poll`/`poll_nocancel`, result 0 or 1). This is a source-conditional correlation to the exact trusted bootstrap, not an observed FD argument or complete interval. It is never silently removed or paired with an invented entry. Any other orphan refuses.

Observed reads must address the exact gate and request exactly the remaining GO bytes, total exactly 64, then request exactly one byte for the sole EOF check. A successful once-only close must target that gate. EXEC_ATTEMPT status writes must target the exact status writer, request exactly the remaining 512-byte suffix, retain each partial interval and total exactly 512 bytes before the sole execve entry. Exact EINTR/EAGAIN read/write and EINTR poll retry projections retain their failed intervals without advancing the BIO engine's confirmed byte count; this makes no general no-effect claim for failed syscalls. Observed endpoint F_GETFL results must retain their required read/write access mode and O_NONBLOCK. Complete flag words remain raw and may differ from READY (for example, kernel write-history bits can change); no whole-word equality is imposed. Successful paired fstat/fstat64 observations require the exact zero return expected by the BIO stat adapter. Signal-mask return words are retained without imposing a zero value. Other prefix operations are restricted to endpoint observations and the fixed bootstrap's ownership/signal-check routes; unknown operations refuse. This finite subset deliberately can refuse a valid native capture with a different attachment boundary or libc route. No native coverage is inferred from the fixture sequence.

The selected exec is a process/image transition, not an ordinary successful same-thread call. Its pending execve entry survives, with an optional exact EJUSTRETURN projection, the old TID, the new TID, and the exec-success → proc:start → lwp-start sequence. An optional fresh thread declaration is resolved by the selected new thread. Old-thread exit and one shadow process exit remain explicit context; the transition retires the old user image without inventing a syscall return. Calls after exec entry but before the transition, reused TIDs, unclosed calls, ambiguous lifecycle timestamp ties, later exec/failure/creation/rights/Mach routes and unresolved declared threads refuse. Ordinary runtime BSD intervals, including unknown names, remain raw observations; an unknown name receives no no-write classification. A pending `exit` entry may be associated with its process exit context as `TerminatingCall`, without inventing a return or interpreting the exit status.
